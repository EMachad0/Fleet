## When to use

Consult this doc whenever you are:

- Creating a new file (component, schema, utility, query, etc.)
- Deciding where a piece of logic belongs (route vs `$lib` vs `src/convex`)
- Moving or renaming files during refactors
- Onboarding a new feature and scaffolding its layout

## Core principle

**Distance equals reuse.**

- Used by one thing → live next to it.
- Used by two or more → promote to `$lib` or `src/convex`.
- Runs on Convex infrastructure → `src/convex`.
- When in doubt, **colocate first**. Promote on the third usage, not the first.

Do not pre-build folder hierarchies "for later".

## Top-level layout

```
src/
  convex/                   # Convex backend — runs on Convex infra
    _generated/             # generated by `bun x convex@latest dev` — never hand-edit
    schemas/                # Zod schemas SHARED between Convex + client (see rule 7)
    functions.ts            # shared zQuery / zMutation / zAction builders (see superforms.md)
    <entity>.ts             # domain functions, one file per entity
  lib/                      # SvelteKit library, imported as `$lib/...`
    components/             # NO index.ts at this level
      ui/                   # shadcn-svelte primitives (CLI-managed); NO index.ts
        button/
          button.svelte
          index.ts
      app/                  # your composites; NO index.ts
        user-menu/
          user-menu.svelte
          index.ts
    forms/                  # createForm wrapper (see superforms.md)
    schemas/                # Zod schemas that do NOT touch Convex
    queries/                # typed wrappers around Convex useQuery / useMutation
    state/                  # *.svelte.ts rune-based cross-page state
    server/                 # server-only utilities
    auth-client.ts          # better-auth client instance
  routes/                   # SvelteKit file-based routes
    <feature>/
      +page.svelte
      +page.server.ts       # auth guard + load
      +page.ts              # universal load (see sveltekit-best-practices.md)
      components/           # route-scoped components
      schemas.ts            # route-local Zod schema
  hooks.server.ts
  app.d.ts
  app.html
```

## Critical rules

### 1. Convex backend stays in `src/convex/` — never move it under `$lib`

`convex.json` declares `"functions": "src/convex/"`. `svelte.config.js` aliases `$convex` → `src/convex`. Mixing Convex into `$lib` muddles build semantics — Convex runs on its own infrastructure, not in the SvelteKit bundler.

### 2. All client library code lives in `src/lib/`, imported as `$lib/...`

Don't create `src/components/`, `src/utils/`, `src/stores/`, etc. — all library code goes under `src/lib/`.

### 3. shadcn in `$lib/components/ui/`; your composites in `$lib/components/app/`

`ui/` is CLI-managed (shadcn). `app/` is hand-written. Never mix them.

### 3a. Folder-per-component, with a local `index.ts` — always

Every component lives in its own kebab-case folder. The folder contains `.svelte` file(s) plus an `index.ts` that re-exports. This applies to shadcn primitives, `$lib/components/app/` composites, and route-local components.

**Single-component folder:**

```
user-menu/
  user-menu.svelte
  index.ts          # export { default as UserMenu } from './user-menu.svelte';
```

**Multi-file folder (shadcn Dialog pattern):**

```
dialog/
  dialog.svelte
  dialog-content.svelte
  index.ts          # import Root from './dialog.svelte'; export { Root, Root as Dialog, ... }
```

Consumers import from the folder: `import { UserMenu } from '$lib/components/app/user-menu'`

Don't create flat `.svelte` files outside folders (e.g. `$lib/components/app/UserMenu.svelte`).

### 3b. No barrel `index.ts` at `components/`, `ui/`, or `app/` level

Don't create `$lib/components/index.ts`, `$lib/components/ui/index.ts`, or `$lib/components/app/index.ts`. Upper-level barrels cause circular imports, worse tree-shaking, and noisy diffs. Only per-component `index.ts` files exist.

### 4. Business logic placement

| Logic kind                               | Location                                    |
| ---------------------------------------- | ------------------------------------------- |
| DB reads/writes, authz, domain rules     | `src/convex/<entity>.ts`                    |
| Route-specific load + form actions       | `src/routes/<path>/+page.server.ts`         |
| Route-only components                    | `src/routes/<path>/components/`             |
| Zod schemas shared with Convex           | `src/convex/schemas/<entity>.ts`            |
| Client-only Zod schemas                  | `$lib/schemas/` or route-local `schemas.ts` |
| `createForm` wrapper                     | `$lib/forms/`                               |
| Reusable types                           | `$lib/types/`                               |
| Pure utilities                           | `$lib/utils/`                               |
| Cross-page client state (runes)          | `$lib/state/<name>.svelte.ts`               |
| Server-only helpers (secrets, node APIs) | `$lib/server/`                              |

Don't build a `$lib/server/` service layer wrapping Convex mutations — put the logic in `src/convex/`.

### 5. Use `$lib/server/` for anything that must never reach the client bundle

SvelteKit refuses to bundle `$lib/server/` into client code. With Convex, this stays small — use it only for secrets in `hooks.server.ts` / `+page.server.ts`, Node-only libraries, or auth glue outside Convex.

### 6. Route colocation — promote to `$lib` on third reuse, not first

Start route-specific. Promote the entire folder to `$lib/components/app/` only when a third consumer materialises.

Don't colocate route-only components in `$lib/components/` "just in case" — that is premature abstraction.

### 7. Zod schema placement — Convex-shared schemas live in `src/convex/schemas/`

| Schema kind                         | Location                         | Convex imports via   | Client imports via         |
| ----------------------------------- | -------------------------------- | -------------------- | -------------------------- |
| Shared with a Convex mutation/query | `src/convex/schemas/<entity>.ts` | `./schemas/<entity>` | `$convex/schemas/<entity>` |
| Used by 2+ routes, no Convex        | `$lib/schemas/<name>.ts`         | —                    | `$lib/schemas/<name>`      |
| Used by exactly one route           | `src/routes/<path>/schemas.ts`   | —                    | relative                   |

Convex functions cannot resolve `$lib`. The `$convex` alias bridges both sides.

Don't duplicate a Zod schema in `$lib/schemas/` and a `v.*` validator in `src/convex/` for the same shape — use `zCustomMutation` + shared schema (see `superforms.md`).

Don't import `$lib/schemas/<entity>` into Convex — it will fail to resolve.

### 8. Rune-based client state goes in `$lib/state/*.svelte.ts`

Export a class or factory — don't export a module-level `$state` variable (importers share a single instance silently).

### 9. File and directory naming

| Thing                   | Convention                  | Example                          |
| ----------------------- | --------------------------- | -------------------------------- |
| Component folder        | kebab-case                  | `user-menu/`, `button/`          |
| Svelte component files  | kebab-case (matches folder) | `user-menu.svelte`               |
| Component binding       | PascalCase via `index.ts`   | `import { UserMenu } from '...'` |
| SvelteKit special files | `+prefix` lowercase         | `+page.server.ts`                |
| TS modules              | kebab-case                  | `format-date.ts`                 |
| Rune state modules      | kebab-case + `.svelte.ts`   | `preferences.svelte.ts`          |
| Route folders           | kebab-case                  | `org-settings/`                  |

## Decision flowchart

1. **Runs on Convex?** → `src/convex/<feature>.ts`. Stop.
2. **Imports a secret or Node-only API?** → `$lib/server/<name>.ts`. Stop.
3. **Used by exactly one route?** → colocate in `src/routes/<path>/`. Stop.
4. **Svelte component?** → shadcn: `ui/<kebab>/`. Yours: `app/<kebab>/`. Always a folder.
5. **Zod schema?** → Convex needs it: `src/convex/schemas/`. Client-only shared: `$lib/schemas/`. One route: route-local.
6. **Rune state?** → `$lib/state/<name>.svelte.ts`.
7. **Pure utility or type?** → `$lib/{utils,types}/`.
8. **Anything else?** → `$lib/<category>/`.

## Patterns

- **Entity ownership:** one Convex file per entity, one shared Zod schema per entity in `src/convex/schemas/`, one route segment per entity. Parallel naming makes grep-driven navigation trivial.
- **Generated code:** never hand-edit `src/convex/_generated/`. Regenerate via `bun x convex@latest dev`.
